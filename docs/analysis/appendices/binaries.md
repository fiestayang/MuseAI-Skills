## 如何解释

下表的文本引用只取首次位置作为入口，包括说明、命令示例或脚本字符串；它不是完整调用关系。无引用不表示无人使用，调用可能来自其他二进制、外部 unit 或缺失构建材料。每项分析深度为接口与分发边界，缺失的函数实现明确保留未知。

## 角色划分与开发含义

- Hatch/daemon/control 相关程序：Shell 暴露进程和权限边界，但 Agent 内循环、授权存储、工具 dispatch、调度算法不能从调用参数恢复。
- Connector CLI：SKILL 与 manifest 描述命令、方法和边界。复用规则应重新接目标 provider API，不应将这些不可读程序作为“已审查 SDK”。
- 媒体、搜索与 artifact helper：看各技能对输入文件、格式和结果的约束；外部模型、API 或编译工具可能仍缺失。
- bun、codex、bwrap、rtc-sidecar：属于环境/执行组件，不能因名字存在就推断已配置、可运行或与某版本线上服务兼容。
- rtc-sidecar-lib：包含 Boost、OpenSSL、ICU、压缩、日志、内存分配等共享库。文件名可提供 ABI/版本线索，不等于完整来源证明或安全版本认证。

`opt/hatch-image/bin/gws` 是零字节占位文件，单列为不可用实现。`npm`、`npx` 是符号链接，指向附带 npm 源码入口，详见[第三方组件](third-party-components.md)。可读 wrapper 的逐行入口分析在[运行时代码目录](../runtime/README.md)。

## 验证限制

未检查 ELF 每条指令、动态依赖实际解析、签名、供应商 release 对应关系或 CVE。SHA256SUMS 的一致性只证明本地文件与仓库清单相符；清单本身不是可信发行签名。跨平台移植、分发权利和供应链来源应在真实集成时核验。
