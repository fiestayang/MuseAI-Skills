## 复用对象

优先复用技能里的领域规则：对象如何消歧、输入怎样齐备、何时读参考、何时调用工具、什么算成功、错误如何恢复。这些规则比复制目录名更有价值。本仓库没有可直接抽出的完整 Agent SDK，也没有开源的同款选择器。

三种实施范围中，默认从第一种开始：

| 方案 | 适用前提 | 最小交付 | 成本与边界 |
|---|---|---|---|
| 已有 Agent 增加技能 | 现有工具调用与权限层可用 | SKILL、必要参考、工具映射、少量行为场景 | 最小改动；先证实可提升任务完成度 |
| 加一层显式技能执行 | 宿主没有发现/按需加载能力 | 文件清单、路由入口、按需加载、可观测调用记录 | 自己实现选择语义，不能宣称复制原算法 |
| 隔离代码执行服务 | 确实要运行不可信代码，且有 Linux 运维能力 | 进程/网络/文件边界、授权代理、恢复与集成验收 | 宿主安全承诺高；不能只拷启动脚本 |

## 最小结构

以下是建议，不是要求为本仓库新增执行器。沿用目标仓库现有目录和测试方式即可。

```text
skills/
  calendar/
    SKILL.md
    references/
      update-rules.md
    manifest.yaml
    eval/
      scenarios.yaml
src/
  skills.ts
  tools/
    calendar.ts
tests/
  skill-routing.test.ts
  calendar-boundary.test.ts
```

技能很少时一个静态清单足够。参考只有超过主文件合理长度或分支确实独立时才拆。没有工具权限差异时不必强行引入 manifest；若已有权限系统，就映射现有权限而非并行造一套审批。

SKILL 正文采用固定但短的结构：适用任务、排除任务、前置状态、分支流程、具体工具输入输出、失败恢复、完成证据。参考文件承担 provider 专项、长格式或领域表。真实秘密、账号 token 和临时响应不进入技能仓库。

## 选择与执行

建议流程由现有 Agent 驱动：读 metadata → 根据任务选候选 → 加载选中正文 → 按条件读参考 → 校验工具输入与授权 → 执行 → 核对业务效果 → 返回结果与剩余事项。路由和工具执行应分别记录，便于分清“选错技能”与“工具失败”。

优先支持显式技能名和清晰的任务描述。遇到相邻能力，使用少量排除规则：旅行计划交 planning；用户明确推进预订再进入 booking；普通邮件与系统专用 Muse Mail 分开；创建文档与查询 Drive 文件分开。不要默认同一任务只能用一个技能，也不要因为元数据中出现词语就加载所有相关技能。

只在已有评测显示规则无法覆盖同义表达、候选规模确实增长时，再比较模型路由或检索方案。先保留任务文本、选择结果、期望技能、失败原因，才有办法判断新路由器是否有收益。当前仓库不能给出向量检索、排序器或缓存失效的实现答案。

别名应解析为一个 canonical ID；记录 requested ID 与 canonical ID，避免重复加载和重复动作。变更后可先用文件版本或进程重载处理更新。没有热更新需求就不引入分布式失效机制。

## 接口边界

### 工具和类型

所有 HTTP、环境变量、JSON、provider 返回从 `unknown` 进入，使用单一 runtime schema 校验并推导类型。业务闭合状态采用 discriminated union，分支穷尽检查。TypeScript 开启 strict、noUncheckedIndexedAccess、exactOptionalPropertyTypes；不靠 any 或双重断言跳过输入验证。

每个 adapter 接收明确账号、对象 ID、参数和任务上下文。日历日期、金额币种、cursor、时区和变体不能用隐含全局默认混合。返回值区分读取成功、业务拒绝、可重试失败、状态不明；保持原 provider ID 和必要诊断字段。

浏览器走 typed transport → 鉴权/解码 → domain command → store。浏览器 bundle 不导入数据库 driver、server 模块或秘密。既有 Node/Python 服务保持原技术栈即可，不为技能文本引入新框架。

### 权限和高损失动作

动作默认策略由执行层落实。用户任务授权、OAuth、审批及单次金额约束分开建模。向用户请求批准前，先形成可审阅对象：收件人与正文、商品和总价、航段和条款。授权一旦已有且输入未变，不重复询问。

资金、删除和不可逆发送要把结果不明作为第一类状态。先检查外部效果再重试；仅在 provider 支持时使用其幂等键。不能自己生成一个字符串就称实现了幂等。记录对应对象和授权摘要，让恢复能定位原请求。

### 状态和异步工作

已有数据库时直接使用。小规模只需 task/run/result/delivery 的必要记录，不复制全套 Muse schema。长期目标和记忆仅在产品确实需要时加入。允许后台观察时，明确停止条件、用户时区、触发证据、输出位置与交付状态。

遗忘从来源和生产者向派生数据追踪；停止任务和删除数据分开。持久化读取经过 canonical decoder；遇到坏历史数据明确导出、校验、导入，避免宽松吞掉错误后继续推断。

### 产物

可编辑源、导出文件和预览各有角色。保留源后渲染检查，再交付用户能访问的真实文件。Sheets 局部 API 改动与 Docs/PPTX 文件替换需要不同 adapter。静态产物注明数据时点，不能把一次快照称为实时应用。

## 验证和迭代

| 阶段 | 最小动作 | 成功证据 |
|---|---|---|
| 基线 | 选 1–2 个真实任务，记录原流程失败点 | 有可复现输入及预期结果 |
| 技能 | 编写主流程和真实工具映射 | 名称、链接、参数可解析；没有引用缺失脚本 |
| 路由 | 正常、同义、相邻任务各一个例子 | 选对技能，必要时组合，排除不相关技能 |
| 边界 | 缺账号、缺 scope、输入变更、非幂等超时 | 不越权、不重复外部动作，准确报告未完成 |
| 结果 | 核对 provider 状态或实际产物 | 成功证据不依赖模型自述 |
| 改进 | 汇总人工纠正、失败类别和额外调用数 | 决定保留、删减规则或调整 adapter |

已有 YAML 场景提供行为题材，不能直接当目标仓库测试 runner。将期望转为可观察断言：是否调用了正确 method、是否在需要确认时停住、是否保留 ID、是否没有多发一笔请求。只写“回答很好”没有回归价值。每个技能文章另列最小验收建议，按实际移植范围选用。

## 不要直接搬走的部分

绝对路径、UID/GID、宿主网络、rootfs 和 bundle pin 都与原部署绑定。二进制跨平台与授权条款要先独立核验。npm 是附带环境组件，不是技能框架的依赖理由。大型数据库 schema 提供领域关系参考，不能替代目标产品自己的数据需求。

本轮交付的是分析与开发指引，没有改变技能行为、引入框架、启动服务或实现上述建议架构。
